# Junior production dependency patch

Security-only release based on freshly fetched `origin/main` commit `113d83139e8a547f6a3980c13a6e9132edb1c90d`. Only Router patch `14e012edb55345431e93eb59363217d1dad9737e` was cherry-picked; no optional offer, billing preparation, readiness endpoint or rollout flags are included. Pins the direct `react-router-dom` dependency to 7.18.2 (within its previous ^7.15.0 compatible range), with its exact matching transitive `react-router` 7.18.2. No overrides, major upgrades, forced updates, audit exceptions, unrelated dependency changes, frontend changes or checkout/form changes are included. Both packages retain Node >=20 and React/ReactDOM >=18 support.

Current official [RSC CSRF advisory](https://github.com/advisories/GHSA-qwww-vcr4-c8h2) identifies 7.18.2 as the patched 7.x version; the upstream [7.18.2 release](https://github.com/remix-run/react-router/releases/tag/react-router%407.18.2) is published. Registry metadata and lockfile integrity were checked against both published 7.18.2 tarballs. Earlier 7.18.0 fixes cover the [route-matching DoS](https://github.com/advisories/GHSA-chx6-hx7r-mcp5), [backslash open redirect](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6), [RSC protocol validation](https://github.com/advisories/GHSA-h8fp-f39c-q6mh), and [SSR constructor injection](https://github.com/advisories/GHSA-337j-9hxr-rhxg). The [document-request CSRF advisory](https://github.com/advisories/GHSA-84g9-w2xq-vcv6) is patched in 7.15.1. Some upstream advisories are specific to Framework/RSC modes; this declarative BrowserRouter app does not use those paths, but that is not an audit waiver and does not substitute for installing the patched release.

The dependency command initially advanced set-cookie-parser 2.7.2 to 2.7.3 within its compatible range. Its original lock entry was retained to avoid unrelated churn, and a fresh isolated `npm ci --ignore-scripts` succeeds with that original version. Machine comparison confirms only react-router and react-router-dom package records change, plus the root exact DOM dependency specification. Every other package record is byte-equivalent after JSON serialization. No service keys/configuration are involved.
